# PulseX Health

PulseX Health is a collaborative healthcare platform designed to connect Patients, Doctors, Hospitals, Ambulance Services, and Blood Banks. The project provides a responsive, easy-to-use interface for booking medical appointments and accessing digital health services.

---

## Tech Stack

The application is built using a modern, lightweight stack focused on clean rendering and fast load times:

*   **Backend Framework**: Node.js + Express.js (v5.2.1)
*   **Template Engine**: EJS (Embedded JavaScript, v6.0.1)
*   **Styling**: CSS3 (Vanilla styling utilizing Flexbox, CSS Grid, and custom CSS variables for modularity and themes)
*   **Scripting**: Client-side Vanilla JavaScript (ES6 modules and event-driven page logic)
*   **Development Tools**: Nodemon (v3.1.14) for live reload in local environment

---

## Features

*   **Responsive Landing Interface**: Fully optimized for desktop, tablet, and mobile viewing.
*   **Certified Doctors Showcase**: A catalog of available healthcare specialists (Cardiology, Dentistry, Neurology, Pediatrics).
*   **Patient Feedback & Reviews**: A clean testimonial section displaying user satisfaction.
*   **Structured Landing & Footers**: Quick links and contact details for patient support.

## Installation Guide

Follow these steps to configure the project locally:

1.  **Clone the Repository**:
    ```bash
    git clone https://github.com/Babul422/PulseX1-Health-.git
    cd finalexam
    ```

2.  **Checkout the Active Branch**:
    The team's active development branch is `sriprakash`. Ensure you are on this branch:
    ```bash
    git checkout sriprakash
    ```

3.  **Install Dependencies**:
    Make sure you have Node.js (v18+) installed. Run:
    ```bash
    npm install
    ```

---

## Run Instructions

Start the server using one of the configured NPM scripts:

### Development Mode (with live reload)
```bash
npm run dev
```

### Production Mode
```bash
npm start
```

Once running, navigate to `http://localhost:3000` in your web browser.

## Team Workflow

We follow standard **Git Flow** practices for code organization and collaborative development:

1.  **Sync Branch**: Always pull the latest changes from `sriprakash` before starting work:
    ```bash
    git pull origin sriprakash
    ```
2.  **Create Branch**: Work on a dedicated branch rather than committing directly.
3.  **Submit PR**: Push your branch and open a Pull Request (PR) against the `sriprakash` branch on GitHub.
4.  **Review & Merge**: Changes will be merged after testing and peer approval.

### Branch Naming Convention

Keep branch names descriptive, lowercase, and hyphens-separated. Prefix names using the categories below:

*   **Features**: `feature/feature-name` (e.g., `feature/appointment-form`)
*   **Bug Fixes**: `bugfix/issue-description` (e.g., `bugfix/nav-responsive`)
*   **Hotfixes**: `hotfix/critical-issue` (e.g., `hotfix/server-crash`)
*   **Documentation**: `docs/topic-name` (e.g., `docs/readme-updates`)

### Commit Message Convention

We adhere to the **Conventional Commits** specification to keep git logs clear and readable:

*   `feat:` New feature implementation
*   `fix:` Bug fixes and corrections
*   `docs:` Documentation modifications
*   `style:` Changes that do not affect code logic (formatting, spacing, CSS cleanup)
*   `refactor:` Logic changes that neither fix a bug nor add a feature
*   `test:` Adding or updating tests
*   `chore:` General tasks, build configuration, package updates

*Example:*
```bash
git commit -m "feat: implement appointment form responsiveness"
```
